15.10 report.py and aggregate.py — reading the numbers back out

Rule 2's other half. These modules never fit anything; they only read results/. That one-way flow is what makes the claim "every number in the report traces to a committed result file" structurally true rather than aspirational.

src/report.pymodule docstring
"""Table builders shared by the narrative notebook and the report.

Every table is assembled from results/*.json, so a number cannot appear in the report
without existing in a committed result file. `pm` formats mean +/- SD to a fixed number
of digits, which keeps the "do not bold a difference smaller than one SD" rule honest:
if the difference does not survive the formatting, it does not survive the argument.
"""

That last clause is a genuinely useful trick and worth restating. Every cell that reports a cross-validated metric is formatted as mean ± SD at a fixed precision:

src/report.pyexcerpt
def pm(mean, sd, digits=4):
    if mean is None:
        return "--"
    if sd is None:
        return f"{mean:.{digits}f}"
    return f"{mean:.{digits}f} +/- {sd:.{digits}f}"

def num(value, spec=".4f"):
    """Format a metric, or `--` when it is null.

    The section 3.2 schema requires an inapplicable metric to be null rather than zero, so
    every table cell has to tolerate one. Rung 1b, for instance, scores `PAY_0` as an ordinal
    rather than fitting a model, so it has no accuracy at a 0.5 threshold.
    """
    return "--" if value is None else format(value, spec)

Because the SD is printed beside the mean in every table, a reader can perform the one-SD test themselves on any row pair without being told the answer. There is no table in the project where a mean appears alone. That is a formatting decision doing ethical work: the easiest way to oversell a 0.002 AUC win is to print the means in a tidy column and leave the variance in a footnote.

The manifest — one flat row per (experiment, label)

experiments/aggregate.pyexcerpt
"""WP19 -- flatten every results/*.json into results/manifest.csv.

The manifest is the single source of truth the report quotes. Every number printed in
the report must trace to a row here, which is what stops a figure and a table
disagreeing because one was retyped.
"""

# Nested containers live in the JSON for the figure builders; flattening them into the
# manifest would produce unreadable cells.
SKIP = {"groups", "reliability_curve", "cost_curves", "subgroup_detail",
        "shap_by_seed", "params"}

def _flat(prefix, value, out):
    if isinstance(value, dict):
        for k, v in value.items():
            if k in SKIP:
                continue
            _flat(f"{prefix}{k}_" if prefix else f"{k}_", v, out)
    elif isinstance(value, (list, tuple)):
        out[prefix.rstrip("_")] = json.dumps(value) if len(value) <= 8 else f"[{len(value)} items]"
    else:
        out[prefix.rstrip("_")] = value

Two deliberate compromises. Short lists are inlined as JSON — the five seeds, the six cost ratios — because they fit in a cell and are more useful visible. Long ones become [501 items], a placeholder saying "this exists in the JSON, look there", because a 501-element threshold grid in a CSV cell is worse than useless. And the SKIP set drops the nested containers entirely: they are structured payloads for the figure builders, not scalars the report quotes. The manifest is optimised for the question "where did that number come from?", not for completeness.

15.11 verify.py — the gate that is not optional

§5.7 argued that an audit you have to perform by reading is an audit that will not be performed. This module is the mechanical version: ten checks, each printing PASS, FAIL or SKIP with a one-line detail, and a non-zero exit code if any failed. It is a pre-submission gate, not a report.

The decorator pattern means adding a check is one function, and the driver catches AssertionError separately from other exceptions — an assertion is a FAIL (a claim is false), while a FileNotFoundError is reported as an ERROR (the check could not run). Conflating the two would let a missing artifact masquerade as a passing suite.

experiments/verify.pyexcerpt
@check("Leakage audit: the hold-out is imported only where licensed")
def _leakage():
    licensed = {"exp11_shap.py", "exp12_stability.py", "exp14_final.py",
                "figures.py", "verify.py"}
    offenders = {}
    for p in sorted(exp_dir.glob("*.py")):
        if p.name in licensed:
            continue
        text = p.read_text(encoding="utf-8")
        hits = [tok for tok in ("test_context", "X_test", "y_test", "test_idx")
                if tok in text]
        if hits:
            offenders[p.name] = hits
    assert not offenders, f"hold-out referenced in selection code: {offenders}"
Why a grep is a legitimate proof here, and where it stops being one

This is textual, not semantic, and that is normally a weakness. It is a strength in this case because of the firewall in §15.4: the only ways to obtain a held-out row are to call test_context or to index splits["test_idx"] yourself. Both are named tokens. There is no arithmetic that produces test rows from training rows, no clever slice, no alias — the indices are in a cached .npz under those exact keys. So "none of these four tokens appears in the file" really does imply "this file cannot see the hold-out".

The honest limits: it is defeated by getattr(data, "test_" + "context"), by a variable named something else holding test rows passed in from elsewhere, and by the five licensed files, which it does not check at all. The first two are not accidents — nobody leaks by dynamic attribute lookup by mistake, and the check is aimed at accidents. The third is the real residual risk, and it is managed by the licence list being short enough to read: three experiment scripts and the figure builder. SHAP's two are licensed because explanation selects nothing; exp14 is the single gate; and figures.py draws the ROC curve that exp14 already computed.

The subtlety flagged in the comment matters. Reading additivity_max_error out of the result file and asserting it is small only verifies that exp11 reported a small number — it would pass even if exp11 computed it wrongly. So the check also loads the cached SHAP matrix and independently verifies two structural facts: the matrix has one column per feature, and the base value is constant across all explained rows. The second is the one that catches real misconfiguration: under interventional perturbation with a fixed background sample the base value is the mean margin over that background and must be identical for every explained row. A per-row base value would mean the explainer was running in a mode other than the one §11.4 claims.

The one environment decision worth recording

Phase 1 pinned Python 3.14. The Phase 2 dependency that was expected to break on it was shap, which pulls numba, and numba historically lags new CPython releases by months. It installed and imported, so no fallback venv was needed — the environment here is Python . The incompatibility that did bite was subtler and was not on anyone's risk list: the enable_categorical / interventional-TreeSHAP interaction in §15.3. Worth internalising as a general lesson — the dependency risk you plan for is usually a clean install failure you find in thirty seconds; the one that costs an afternoon is two libraries that each work perfectly and disagree about what a flag means.

Rule 2 says no number is retyped. But this guide is a hand-written HTML file. How is that consistent — and what would go wrong if it were not?

The prose is hand-written; the numbers are not. Every figure in this guide is either a <span data-v="…"> placeholder or a chart rendered by JavaScript, and both are filled at build time from a payload that guide/build_guide.py extracts from results/*.json. The build fails loudly if the injection marker is missing or if any placeholder is left unresolved, so a half-built page cannot ship looking complete.

What would go wrong without it is not abstract. Several numbers in this guide moved after it was first drafted — the trial budget rose from the planned 60–80 to , and the Bayes-floor check returned contradictory rows instead of the predicted 21, which is why §14.6 abandons that argument rather than making it. Under hand-typed numbers, each of those changes would require finding every occurrence across sixteen sections and a report, and the failure mode is asymmetric: you fix the ones you remember and miss one, leaving a document that contradicts itself in a single sentence. That is exactly the kind of error a marker finds and an author cannot, because the author knows what the number was supposed to be.

A classmate says the src/ package is over-engineering for a single-author assignment, and one notebook would have been fine. Give the strongest version of their case, and then the actual answer.

Their case is decent. There is real overhead: twelve modules to navigate instead of a linear read, an import graph to keep acyclic, artifacts to invalidate when something upstream changes, and a genuine loss — in a notebook you see the output beside the code that made it, which is a better medium for exploration. Phase 1 was a notebook and was better for being one. Abstraction also has a cost in reviewability: cv_evaluate(X, y, factory, folds) hides the loop, and a reader who wants to check the loop has to open another file.

The answer is that the decisive advantages are not about authorship count. Restartability: fourteen experiments and a few hours of compute cannot live in a kernel, because the first crash costs the whole run. Caching: without artifacts/, nine experiments refit the same tuned model. Auditability: the leakage grep in §15.11 is only a proof because training_context and test_context are separate importable functions — in a notebook where X_test is in the global namespace from cell 8 onward, every subsequent cell can see it and no mechanical check is possible. Comparability: Rule 1 guarantees exp01 and exp14 used the same evaluation path, which in a notebook would be a matter of scrolling up and hoping.

And one concession in their favour: the narrative notebook still exists, and still carries the story. The package did not replace it — it took the computation out of it so it could execute in under a minute. Both halves got better at their actual job.
