Section 6The complexity ladder: research question 1, quantified

Phase 1 asked whether the performance gain from ensembles justifies the loss of rule-based interpretability. That is not a question a single XGBoost number can answer — you cannot read a trade-off off one point. It needs a sequence of models where each step adds exactly one capability, so the gain and the cost of that step can both be measured. Eight rungs, one controlled comparison each.

6.1 Why a ladder rather than a benchmark table

The usual way to present a model is: here is my model, here are three competitors, mine wins. That answers "which is best?", which is not the question Phase 1 committed to. The commitment was about a trade-off, and a trade-off has two axes. So the design constraint on this experiment is that consecutive rungs must differ in one thing:

0→1
constant → one rule Adds the ability to read a single feature. Isolates the value of any information at all.
1→1b
one rule → one ordering Same feature, same single column, but ranked on the raw code rather than split in two. Isolates the cost of insisting on a readable threshold.
1b→2
one feature → all features, linearly Adds 22 more columns but allows only additive linear effects. Isolates the value of breadth.
2→3
linear → non-linear, still readable A single depth-tuned tree. Adds interactions and non-monotonicity while keeping a human-auditable rule set. Isolates the value of non-linearity.
3→4
one tree → many trees, averaged A random forest. Adds variance reduction and destroys direct readability. Isolates the value of bagging.
4→5
bagging → boosting XGBoost at library defaults. Same ensemble cost, different construction: sequential error-correction instead of independent averaging. Isolates the value of boosting.
5→6
defaults → tuned §7's Optuna configuration. Same algorithm, same interpretability cost. Isolates the value of tuning.

Because each step is a single change, the overall gain decomposes into attributable pieces. That decomposition is the actual answer to Q1 — and, as it turns out, it reallocates credit in a way that contradicts the usual story about why boosting wins.

6.3 Rung 0 and the accuracy trap

Predicting "nobody defaults" for all 23,955 training clients achieves accuracy. That is not a coincidence or a quirk — it is exactly 1 − prevalence = 1 − , because every negative is correct and every positive is wrong.

What rung 0 is actually for

Its recall is 0.0000 and its ROC-AUC is 0.5000. A model with accuracy that never identifies a single default has negative business value: it would be deployed, it would approve every applicant, and the entire default book would land unflagged.

So rung 0 exists to pre-empt a specific failure mode in reporting, not to be a competitor. The tuned model's accuracy is — about four points above the trivial constant. Anyone quoting that 82% as the headline has said almost nothing, and rung 0 is the row that proves it. This is why accuracy appears in exactly one table in the whole report, with rung 0 directly above it, and is never optimised against.

6.4 Rungs 1 and 1b: the price of one readable rule

Rung 1 is a depth-1 decision tree on PAY_0 alone — the most interpretable non-trivial model that exists. One comparison, one threshold, reproducible on paper. It reaches .

Phase 1 reported 0.690 for "PAY_0 alone", from the notebook that was never committed. The ladder had to recover that benchmark, and at first it appeared not to. The resolution is the single most instructive result in this experiment.

Why a stump scores lower than the column

A depth-1 tree can only cut PAY_0 into two groups. Whichever cut it picks, every code on one side is treated as identical — so the model emits exactly two distinct scores, and ROC-AUC over two score levels is a single point on the ROC curve joined to the corners.

Rung 1b fits nothing at all. It ranks clients by the raw PAY_0 integer and computes ROC-AUC on that ordering directly. Nine distinct score levels instead of two, and it reaches — above the stump, and a match for the Phase 1 figure.

So ROC-AUC is the measured price of the single readable threshold, with the feature set held completely constant. That is the first rung of the interpretability cost, and it is paid before any ensemble is involved. Recovering the lost benchmark and explaining the discrepancy is strictly better than quietly reporting one number.

Rung 1b also defines the yardstick the rest of the project is measured against. "Better than nothing" is rung 0; "better than the one obvious rule a credit officer would already use" is rung 1b, and it is a much harder bar.

6.5 Rungs 2 and 3: breadth, then non-linearity

Logistic regression on all 23 features reaches — so adding 22 columns under a linear additive constraint buys over ranking on PAY_0 alone. A single depth-tuned tree then reaches , so relaxing linearity buys a further .

That ordering is itself a finding, and §2's encoding discussion predicted it: the PAY_n response is non-monotonic (default rate falls from code −2 to code 0, then rises steeply), and a linear model must fit a single sign to a U-shape. It cannot represent the pattern the data actually contains. The tree can, with two stacked splits.

Say this plainly in the report, and in the viva

Rungs 2 and 3 are untuned internal reference implementations — LogisticRegression() and a tree with only its depth selected. They are not Izak's Decision Tree submission or Declan's Logistic Regression submission, both of which are separately tuned individual deliverables. Their purpose is to locate XGBoost on a capability axis under matched conditions, not to compete. Presenting an untuned baseline as a teammate's result would misrepresent their work, and that would be a worse failing than omitting the rungs entirely.

6.6 Rungs 4–6: where the ensemble gain actually comes from

This is the part that does not match the folklore. Decompose the climb from the single tree to the final model:

The finding: untuned boosting does not beat bagging here

Rung 5 scores and rung 4 scores . Out-of-the-box XGBoost is numerically behind a default random forest — , comfortably inside one fold-SD, so the correct statement is indistinguishable, not "worse". Either way, the claim "boosting beats bagging" is not supported by these data at default settings.

What is supported: boosting beats bagging once tuned. The entire ensemble advantage in this project is of tuning, not the choice of ensemble family. Mechanistically this is what §3.3's regularised objective predicts — a forest of fully-grown unpruned trees has no real capacity dial, whereas boosting's performance is a function of eta × n_estimators × depth × shrinkage, which is precisely why it responds to search. An untuned boosted model is a partially specified model.

The verdict, with its conditional attached

The gain is real and large. ROC-AUC over the one-column yardstick is roughly fold-SDs — not a rounding artefact, not a seed effect. In PR-AUC, the metric that tracks the minority class, it is → , a relative improvement of . At a 22% base rate that is a materially better ranking of who will default.

The interpretability cost is also real. Rungs 0–3 are reproducible by hand on paper. Rung 6 is not reproducible by hand at any effort — the honest entry in that column is "not directly available".

So Q1's answer is conditional, and the condition is Q2. The gain justifies the loss if and only if the post-hoc explanation is good enough to substitute for direct readability in an audit. That is not a rhetorical hand-off: it is why §11 computes SHAP and why §12 tests whether those explanations survive reseeding. A ladder on its own establishes that there is a price to pay; it cannot establish that the price is worth paying.

Where this lands in the submission

This table is Table 1 in the body — the first table the marker sees, and the one that frames the whole report as a trade-off study rather than a leaderboard. The interpretability-cost column is the reason it works: without it the table is just eight AUCs, and Q1 is being answered on one axis. Figure 1 is the widget above, rendered through plotting.save_fig in the Phase 1 house style.

Self-check: isn't rung 1b cheating? It fits no model at all.

It fits nothing, and that is exactly why it belongs. The question "what does the modelling buy?" requires a baseline that involves no modelling, and "sort the clients by their most recent repayment status" is a procedure a credit officer could execute with a spreadsheet. If the whole pipeline could not beat that, it would not be worth deploying.

It also has no free parameters, so it cannot overfit, which makes it an unusually trustworthy reference point. Note that it is reported with brier as null rather than 0 — a raw PAY_0 code is not a probability, so a Brier score would be meaningless. The §3.2 schema rule is that an inapplicable metric is null, never zero, precisely so that this kind of row cannot be silently averaged into a comparison.

Self-check: the random forest's interpretability cost is 692,674. Is that a real number or a rhetorical one?

Real, and counted — total nodes across all 100 trees of a default RandomForestClassifier, which grows every tree to purity on 24k rows. The point of printing it rather than writing "uninterpretable" is that it makes the column a measurement on a single scale running from 1 to ~10⁵, so the trade-off can be plotted on a log axis instead of asserted in prose.

The two XGBoost rungs are serialised as tree counts ( boosted trees for the tuned model, depth ≤ ) rather than node counts, so they are not on the same footing as the forest's figure and the widget labels them accordingly. The qualitative conclusion is unaffected: both are three to five orders of magnitude beyond what a human reads, and the honest cell for both is "not directly available — see SHAP".

Self-check: why is the ladder CV-only? Wouldn't test-set numbers be more convincing?

They would be differently convincing, and they arrive in §14. The ladder's job is model selection and capability attribution, which is a training-portion activity: it compares eight configurations and it is the experiment that decides which one is carried forward. §5.6's licensing table gives test-set access to exactly one experiment plus the SHAP packages, because every additional look at the test set inflates the optimism of the final reported number.

It also matters that CV gives a spread. The 25-fit SD is what licenses the statement that rungs 4 and 5 are indistinguishable while rungs 5 and 6 are not. A single test-set number per rung would give eight point estimates and no way to tell which gaps are real — which is how a 0.002 difference ends up bolded.
